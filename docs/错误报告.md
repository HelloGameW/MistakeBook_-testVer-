# MistakeBook CI 错误报告（0.2.6 → 0.5.1 全量复盘）

> 本报告记录 Codemagic CI 与本地验证中遇到过的**全部**错误，按轮次、错误原文、根因、修复、防复发规则归档。
> 最后更新：0.5.3（构建号 23）。

## 二、根因分类

- **A 类 · iOS 专属代码本机不可见**（#1、2、5、13、14、15、16、17、20）：`#if os(iOS)` 文件在 Windows 构建中是空模块，任何类型错误只有 CI 能发现。这是出现频率最高的类别。
- **B 类 · 运行时语义**（#7、8、10、11）：编译期完全无信号，只有测试真正执行才暴露。
- **C 类 · 手写失误**（#3、4、12、13、18）：参数顺序、初始化形式、作用域细节。
- **D 类 · 环境差异**（#6、18 的 NSURL 桥接）：Xcode 26 / Windows Foundation 与预期不符。
- **E 类 · 流程**（19）：绕过版本脚本手改版本号。

## 三、防复发清单（每次同步前逐项执行）

1. **编译**：`swift build` 7 个可编译目标（Contracts/Intelligence/Workflow/Export/UI/TestSupport/PreviewSupport）全绿；`Storage` 在 Windows 不可编译属预期。
2. **语法**：tree-sitter 全量解析（已知误报白名单：ImportFlowView `try? await`、LocalAppService 多处 `try await` 条件式）。
3. **SwiftUI 形态**：`Section("标题") { }` 之后不得接 `header:`/`footer:`（全仓库扫描脚本）；巨型 body（>90 行 ViewBuilder 表达式）必须拆分为子视图属性。
4. **weak-self 闭包**：`guard let self` 作用域之外不得有隐式 self 成员访问；do/catch 后的状态复位必须移入分支内。
5. **XCTest**：断言宏自动闭包内不得出现 `await`；访问模块 internal 符号的测试文件必须 `@testable import`。
6. **init/调用点核对**：新增或修改的 init 与全部调用点逐个核对参数标签、顺序、个数。
7. **构造器参数顺序**：新代码中的契约构造器（AppSettings、RecordQuery、ImageTransformRequest 等）与契约定义逐参数对照。
8. **@Model 属性名**：不得与 `PersistentModel` 协议成员（`isDeleted`、`persistentModelID`、`id` 等）同名。
9. **Date 相等**：任何经 Codable 往返的 Date 不得做严格相等比较（ISO8601 秒级截断）。
10. **渲染缩放**：测试中的 `UIGraphicsImageRenderer` 必须 `format.scale = 1`。
11. **版本号**：只允许通过 `Scripts/bump-version.sh bugfix|feature` 变更，xcconfig/README/VERSIONING 三处必须一致；禁止手改。
12. **同步前 diff**：核对同步到 GitHub 仓库的文件清单与预期完全一致（防止带入未审查改动）。

## 四、经验总结

- 所有错误中没有一个是"复杂逻辑写错"，全部集中在**接口形态、作用域细节、平台差异、数据精度**这类只有真实编译器/真实运行时才能暴露的层面。
- 本地 Windows 工具链已证明价值（#18 一轮拦下 5 个），但它看不见 iOS 专属代码——因此**每轮只交付最小变更**、并把错误行（`error:` 原文）随日志带回，是最有效的闭环方式。
